# 设计与协作说明

## 需求理解与取舍

任务书允许 CLI 加本地文件达到基础分，Web 不额外加分，因此选择 Python 3.11+ 标准库 CLI 和 SQLite。这个取舍把时间投入到真实持久化、并发安全、AI 降级、审计和评测，而不是无助于验收的前端页面。

主要假设如下：工单公开编号按 UTC 日期递增；重复工单定义为同提交人、24 小时内、规范化标题和描述完全相同；状态只能按显式状态机流转；AI 分类限定为 `account_access`、`software`、`network`、`hardware`、`facilities`、`other`，新工单可以暂时是 `unclassified`；AI 结果必须先进入 `pending`，人工审核才可生效。

## 风险与加固

| 风险 | 加固方式 | 证据 |
|---|---|---|
| 空标题、超长文本和非法枚举 | 领域校验、数据库 CHECK、CLI 参数约束 | domain/repository 测试 |
| SQL 注入或筛选字段注入 | 全部参数化查询，筛选列 allowlist | repository 测试 |
| 重复提交导致脏数据 | 规范化指纹、24 小时事务内查重 | reliability 并发测试 |
| 并发状态覆盖 | `BEGIN IMMEDIATE` 与版本条件更新 | stale-version 测试 |
| 非法状态跳跃 | 显式状态转换表 | 状态机测试 |
| 密钥泄漏 | 密钥只读环境变量，不进入库、日志和异常 | HTTP 错误测试 |
| 模型返回 JSON 越界 | 严格字段集合、枚举和长度校验 | schema 测试 |
| 模型服务超时、401、429、5xx | 稳定错误码和 failed 建议，核心功能继续可用 | HTTP/验收测试 |
| 提示注入改变分诊结果 | 系统指令与用户数据分离，hardened Prompt 明确数据不可信 | Prompt 与评测集 |
| 审核重复或越权生效 | pending 条件更新、单事务审计、审核动作校验 | review 测试 |

## Prompt 与 AI 协作

baseline Prompt 只规定输出格式；hardened Prompt 明确标题和描述是不可信数据，忽略角色冒充和“改变分类/优先级”的文本。用户内容仅作为 JSON 数据消息发送，避免把工单正文拼进系统指令。任务书的打印机缺墨注入原文保存在评测集，预期仍为 `hardware/P2`，而不是恶意要求的 `account_access/P0`。

真实 API 采用 OpenAI 兼容 `/chat/completions` 协议，温度固定为 0，响应最多读取 64 KiB。测试使用本机 HTTP 服务验证真实 HTTP 请求、Bearer 头、协议错误和降级路径，不把固定答案冒充模型结果。

本项目使用 Codex 子代理完成分任务实现和只读审查，主控在每个阶段重新运行聚焦测试、完整回归、编译检查和 `git diff --check`，再创建小步提交。审查发现任务 4 的时间注入和必需版本契约缺口后，补充失败测试、修正并单独提交修复。

## 已知限制

没有有效在线 API 配置时，自动化测试不会声称真实模型准确率；演示脚本会明确提示操作员配置后再运行。评测指标依赖实际提供商输出，固定评测集和 Prompt 版本会写入报告，便于同集复测，但不把一次运行外推成通用模型能力。
